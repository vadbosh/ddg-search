# ddg-search

Установщик MCP-сервера поиска DuckDuckGo
([duckduckgo-mcp-server](https://github.com/nickclyde/duckduckgo-mcp-server))
в Claude Code, Codex и Opencode на Linux и macOS. Вместе с сервером ставится
правило: модель ищет через этот сервер, а не через встроенные инструменты
поиска.

[English version](README.md)

> [!IMPORTANT]
> В Codex установщик выключает встроенный веб-поиск. В `~/.codex/config.toml`
> он пишет `web_search = "disabled"` и отключает приложение
> `connector_openai_search_service`. После этого Codex ищет только через
> ddg-search. Ещё установщик разрешает Codex вызывать инструменты ddg-search
> без подтверждения (`default_tools_approval_mode = "approve"`). Все три
> инструмента только читают.
>
> `./uninstall.sh` возвращает прежние настройки поиска и удаляет запись
> ddg-search вместе с этим разрешением. Чтобы встроенный поиск остался
> включённым, запустите установку как `./install.sh --keep-codex-search`.
> Подробности — в разделе [«Что куда ставится»](#что-куда-ставится).

## Зачем extra [browser]

DuckDuckGo проверяет TLS-отпечаток клиента. По умолчанию сервер ходит в сеть
через httpx. Если DuckDuckGo блокирует отпечаток httpx, он отвечает пустой
страницей с кодом HTTP 202, и любой поиск возвращает одно и то же:

```
No results were found for your search query. This could be due to DuckDuckGo's
bot detection or the query returned no matches.
```

Extra `[browser]` ставит `curl_cffi`. С ним сервер повторяет заблокированный
поиск с TLS-отпечатком Chrome. Установщик всегда ставит этот extra и
фиксирует версию сервера:

```
uvx --python 3.12 duckduckgo-mcp-server[browser]==0.7.0 --fetch-backend auto --ref-url-threshold 0
```

Версия сервера меняется только с релизом этого репозитория. Она задана
константой `VERSION` в `lib/wire.py`.

`--fetch-backend auto` делает то же для страниц. По умолчанию сервер
загружает страницу только через httpx. С `auto` он повторяет запрос через
`curl_cffi`, если сайт ответил кодом 403 или проверкой Cloudflare. 2026-11-13
`extension.umn.edu` ответил httpx кодом 403, а через `auto` отдал страницу
(2381 знак).

Ассистенты запускают эту команду не напрямую, а через
`python3 ~/.local/share/ddg-search/throttle.py`, передавая её как аргументы.
Прокладка отправляет вызовы `search` в DuckDuckGo по одному, с паузой не
меньше `DDG_MIN_INTERVAL` секунд (по умолчанию 2). Несколько поисков сразу
DuckDuckGo блокирует: прогон, начавшийся с шести параллельных поисков, получил
«No results» на 25 поисков из 31. Остальные вызовы, включая `fetch_content`,
не задерживаются.

Очередь общая для всех сессий ассистентов одного пользователя: две сессии,
которые ищут одновременно, тоже идут по одному поиску. Каждый поиск ждёт
блокировку файла `~/.local/state/ddg-search/search.lock`, а в самом файле
записано время последнего поиска. `uninstall.sh` удаляет этот файл.

`--ref-url-threshold 0` оставляет в результатах поиска полные адреса. По
умолчанию сервер заменяет адрес длиннее 120 знаков меткой `ref://`, и модели
нужен лишний вызов `expand_link`, чтобы увидеть, куда ведёт ссылка.

## Что нужно

- python3 версии 3.8 или новее: на нём установщик правит конфигурацию
- [uv](https://docs.astral.sh/uv/): ассистенты запускают сервер через `uvx`.
  Если у uv нет Python 3.12, его скачает `./install.sh`, когда будет скачивать
  сервер

Без uv `./install.sh` останавливается и печатает команду установки uv.

## Установка

```bash
git clone https://github.com/vadbosh/ddg-search ~/src/ddg-search
cd ~/src/ddg-search
./install.sh
```

Потом перезапустите Claude Code, Codex и Opencode, если они запущены: список
MCP-серверов они читают только при старте.

| Параметр | Что делает |
|---|---|
| `--dry-run` | печатает изменения, ничего не пишет |
| `--ide NAME` | ставит в одного ассистента: `claude`, `codex` или `opencode` |
| `--no-rule` | ставит только MCP-сервер, без правила |
| `--search-backend B` | `auto` (по умолчанию), `httpx` или `curl` |
| `--no-server` | пишет только конфигурацию: не проверяет uv и не скачивает сервер |
| `--keep-codex-search` | не выключает встроенный веб-поиск Codex |

В режиме `auto` поиск сначала идёт через httpx, а если DuckDuckGo его
заблокировал, повторяется через `curl_cffi`. В режиме `curl` каждый поиск
сразу идёт через `curl_cffi`. 2026-11-13 DuckDuckGo отвечал на запросы httpx
кодом HTTP 200. На отпечаток Chrome у `curl_cffi` он со второго поиска отвечал
кодом HTTP 202 и страницей проверки на бота. Такую страницу сервер выдаёт как
«No results»
([issue #78](https://github.com/nickclyde/duckduckgo-mcp-server/issues/78)).
Поэтому по умолчанию стоит `auto`.

Повторный запуск установщика ничего не меняет. Прежде чем перезаписать файл,
установщик копирует его в `~/.local/state/ddg-search/backups/`. За пределами
`$HOME` он ничего не пишет.

## Что куда ставится

| Ассистент | Запись сервера | Правило |
|---|---|---|
| Claude Code | `~/.claude.json`, ключ `mcpServers`; ещё `~/.claude/mcp.json`, если этот файл есть | `~/.claude/rules/` |
| Codex | `~/.codex/config.toml`, секция `[mcp_servers.ddg-search]`, с `default_tools_approval_mode = "approve"` | `~/.codex/memories/` и строка с `@` в `~/.codex/AGENTS.md` |
| Opencode | `opencode.json`, ключ `mcp`, с `"codemode": false` | `~/.config/opencode/instructions/`, в списке `instructions` |

С `"codemode": false` Opencode показывает инструменты сервера как обычные:
`ddg-search_search` и `ddg-search_fetch_content`. Правило называет именно их.

Без `default_tools_approval_mode = "approve"` Codex спрашивает разрешение
перед каждым поиском и каждой загрузкой страницы. Все три инструмента сервера
только читают.

У Codex есть собственный инструмент веб-поиска, `web.run`, и по умолчанию он
включён. Пока он доступен, Codex искал через `web.run`, а не через ddg-search,
хотя правило это запрещает. Тот же инструмент приходит к модели и как
приложение, `codex_apps.search_service.web_run`, а на него `web_search` не
действует. Поэтому установщик ещё и пишет `web_search = "disabled"` в начало
`~/.codex/config.toml` и добавляет `[apps.connector_openai_search_service]` с
`enabled = false`. Выключается только это приложение, остальные приложения
Codex работают как раньше. Прежние значения установщик сохраняет в
`~/.local/state/ddg-search/codex-web-search`, и `./uninstall.sh` их
возвращает. Чтобы встроенный поиск остался включённым, запустите
`./install.sh --keep-codex-search`. Если ddg-search в Codex отключён,
встроенный поиск установщик не трогает.

Установщик меняет только запись с именем `ddg-search`. В ней он задаёт
команду, аргументы и переменную `DDG_SEARCH_BACKEND`. Остальные ключи записи,
например `startup_timeout_sec` или `DDG_REGION`, он сохраняет. Другие серверы
не трогает.

Если установщик не может прочитать файл конфигурации, например сломанный
`opencode.json`, он этот файл не меняет и завершается с кодом 1. Остальных
ассистентов он при этом всё равно настраивает.

`config.toml` у Codex установщик правит как текст. Он так же отказывается
работать, если `ddg-search` там записан inline-таблицей
(`ddg-search = { … }` в `[mcp_servers]`). Перепишите запись таблицей
`[mcp_servers.ddg-search]` или удалите её и запустите установщик снова. На
Python 3.11 и новее установщик ещё и разбирает файл. Он отказывается, если
файл не разбирается или перестал бы разбираться после правки.

Оформление файла может измениться: JSON записывается обратно с отступом в два
пробела, а в `config.toml` переводы строк становятся LF.

### Отключённые серверы

В некоторых настройках MCP-сервер отключают, перенося его запись во второй
файл: `~/.claude/mcp-disabled.json` для Claude Code,
`~/.codex/mcp-disabled.toml` для Codex. Если `ddg-search` лежит в таком файле,
установщик обновляет запись там и сервер не включает. В Opencode он сохраняет
`"enabled": false`.

## Удаление

```bash
./uninstall.sh            # или --dry-run, --ide NAME
```

Скрипт удаляет запись сервера, правило и ссылки на правило. Если правило
правили вручную, скрипт сначала копирует его в
`~/.local/state/ddg-search/backups/`. Кэш uv он не чистит. Скачанный пакет удаляет команда `uv cache clean duckduckgo-mcp-server`.

## Тесты

```bash
bash tests/test_install.sh   # во временном HOME; настоящую конфигурацию не трогает
bash tests/test_update.sh    # update.sh на копии репозитория, PyPI заменён файлом
bash tests/test_throttle.sh  # throttle.py на поддельном сервере: поиски по одному
bash tests/docker.sh         # в Docker: наборы тестов под bash 3.2 и Python 3.10, затем настоящая установка
```

У `tests/docker.sh` три этапа:

- `unit`: запускает наборы тестов под bash 3.2 — эта версия стоит в macOS.
- `py310`: запускает наборы под Python 3.10, где нет `tomllib`.
  Там установщик правит `config.toml` без парсера.
- `e2e`: на чистом Debian ставит сервер и запускает его из записи каждого
  ассистента. Затем выполняет один поиск через MCP и проверяет, что поиск
  вернул ссылки. Этому этапу нужна сеть.

`tests/mcp_probe.py claude` проверяет поиск так же, но с конфигурацией этой
машины.

## Обновление сервера

`./release.sh check` заодно спрашивает у PyPI, какая версия
`duckduckgo-mcp-server` самая новая. Если она новее закреплённой, проверка
печатает, например:

```
upstream:     0.8.0 on PyPI, pinned 0.7.0 — ./update.sh
```

Эта строка только для сведения: на код выхода она не влияет, а без сети
пишет `not checked`.

`./update.sh` переводит закреплённую версию на самую новую или на указанную
(`./update.sh 0.8.0`). Шаги по порядку:

1. Останавливается, если в рабочем дереве есть незакоммиченные изменения.
2. Останавливается, если у этой версии больше нет extra `[browser]`.
3. Меняет `VERSION` в `lib/wire.py`.
4. Запускает `tests/test_install.sh` и, если не указан `--no-docker`,
   `tests/docker.sh e2e`: новый сервер на чистом Debian и по одному
   настоящему поиску через MCP для каждого ассистента.
5. Добавляет изменение в `## Unreleased` в `CHANGELOG.md`.

Если какой-то шаг не прошёл, скрипт возвращает прежнюю версию. Он ничего не
коммитит, не ставит тег и не устанавливает. После него просмотрите
`git diff`, выпустите релиз и запустите `./install.sh` на каждой машине.

## Релиз

`./release.sh check` сверяет версию в `CHANGELOG.md`, git-тег, установленные
копии правила и записи сервера в ассистентах. Если что-то расходится, он
завершается с кодом 3. `./release.sh tag` создаёт тег.
